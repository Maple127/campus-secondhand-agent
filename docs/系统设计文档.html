1. 管理员账号管理

1.1 登录认证流程

管理员登录认证流程负责验证管理员身份，确保只有合法用户才能访问系统管理功能。

序列图

┌─────────┐ ┌─────────────┐ ┌──────────────┐ ┌────────────┐ ┌──────────┐ │ 用户 │ │ 浏览器 │ │AdminController│ │AdminRepository│ │ 数据库 │ └────┬────┘ └──────┬──────┘ └───────┬──────┘ └─────┬──────┘ └────┬─────┘ │ │ │ │ │ │ 1.访问登录页 │ │ │ │ │─────────────────>│ │ │ │ │ │ 2.GET /admin/login │ │ │ │ │─────────────────────> │ │ │ │ │ │ │ │ │ 3.返回登录页面 │ │ │ │ │<───────────────────── │ │ │ │ │ │ │ │ 4.提交登录表单 │ │ │ │ │ (username,password)│ │ │ │ │─────────────────>│ │ │ │ │ │ 5.POST /admin/doLogin│ │ │ │ │ (username,password) │ │ │ │ │─────────────────────> │ │ │ │ │ │ │ │ │ │ 6.findByUsername│ │ │ │ │ AndPassword │ │ │ │ │─────────────────>│ │ │ │ │ │ 7.SELECT查询 │ │ │ │ │───────────────>│ │ │ │ │<───────────────│ │ │ │ │ │ │ │ │ 8.返回Admin对象 │ │ │ │ │<─────────────────│ │ │ │ │ │ │ │ 9a.登录成功 │ │ │ │ │ 重定向到仪表盘 │ │ │ │ │<─────────────────│ │ │ │ │ │ │ │ │ │ 9b.登录失败 │ │ │ │ │ 重定向回登录页 │ │ │ │ │<─────────────────│ │ │ │

流程说明

  1. 用户访问登录页面 /admin/login
  2. 系统返回登录表单页面
  3. 用户填写用户名和密码并提交
  4. 后端调用 AdminRepository.findByUsernameAndPassword() 验证凭证
  5. 验证成功：将管理员信息存入Session，重定向到仪表盘
  6. 验证失败：返回错误消息，重定向回登录页

1.2 退出登录流程

退出登录流程确保管理员安全退出系统，销毁Session以防止未授权访问。

序列图

┌─────────┐ ┌─────────────┐ ┌─────────────┐ │ 用户 │ │ 浏览器 │ │AdminController│ └────┬────┘ └──────┬──────┘ └──────┬──────┘ │ │ │ │ 1.点击退出登录 │ │ │─────────────────>│ │ │ │ 2.GET /admin/logout│ │ │───────────────────>│ │ │ │ │ │ 3.session.invalidate()│ │ │ │ │ 4.重定向到登录页 │ │ │<─────────────────│ │

流程说明

  1. 用户点击"退出登录"链接
  2. 后端调用 session.invalidate() 销毁Session
  3. 重定向到登录页面

1.3 密码修改流程

密码修改流程确保管理员可以安全地更新密码，包含严格的验证机制。

序列图

┌─────────┐ ┌─────────────┐ ┌─────────────┐ ┌────────────┐ ┌──────────┐ │ 用户 │ │ 浏览器 │ │AdminController│ │AdminRepository│ │ 数据库 │ └────┬────┘ └──────┬──────┘ └──────┬──────┘ └─────┬──────┘ └────┬─────┘ │ │ │ │ │ │ 1.访问修改密码页 │ │ │ │ │─────────────────>│ │ │ │ │ │ 2.GET /admin/changePassword│ │ │ │ │───────────────────>│ │ │ │ │ │ 3.检查登录状态 │ │ │ │ │─────────────────>│ │ │ │ │ │ │ │ │ 4.返回修改密码页面 │ │ │ │ │<───────────────────│ │ │ │ │ │ │ │ │ 5.提交修改表单 │ │ │ │ │ (oldPassword, │ │ │ │ │ newPassword, │ │ │ │ │ confirmPassword) │ │ │ │─────────────────>│ │ │ │ │ │ 6.POST /admin/changePassword│ │ │ │ │ (oldPassword, │ │ │ │ │ newPassword, │ │ │ │ │ confirmPassword) │ │ │ │ │───────────────────>│ │ │ │ │ │ 7.验证原密码 │ │ │ │ │─────────────────>│ │ │ │ │ │ 8.查询验证 │ │ │ │ │───────────────>│ │ │ │ │<───────────────│ │ │ │ │ │ │ 9a.验证失败 │ │ │ │ │ 返回错误信息 │ │ │ │ │<─────────────────│ │ │ │ │ │ │ │ │ │ 9b.验证成功 │ │ │ │ │ 保存新密码 │ │ │ │ │ │ │─────────────────>│ │ │ │ │ │ 10.UPDATE │ │ │ │ │───────────────>│ │ │ │ │<───────────────│ │ │ │ │ │ │ 11.重定向到仪表盘 │ │ │ │ │<─────────────────│ │ │ │

流程说明

  1. 用户访问修改密码页面
  2. 系统验证用户已登录
  3. 返回修改密码表单页面
  4. 用户填写原密码、新密码、确认密码
  5. 后端验证原密码是否正确
  6. 验证新密码和确认密码是否一致
  7. 更新数据库中的密码
  8. 重定向到仪表盘并显示成功消息

2. 商品审核与管理

2.1 商品发布流程

商品发布流程允许用户提交二手商品信息，提交后进入审核队列等待管理员审核。

序列图

┌─────────┐ ┌─────────────┐ ┌──────────────┐ ┌────────────┐ ┌──────────┐ │ 用户 │ │ 浏览器 │ │ProductController│ │ProductRepository│ │ 数据库 │ └────┬────┘ └──────┬──────┘ └───────┬──────┘ └─────┬──────┘ └────┬─────┘ │ │ │ │ │ │ 1.填写商品信息 │ │ │ │ │ (name,price, │ │ │ │ │ description, │ │ │ │ │ category) │ │ │ │ │─────────────────>│ │ │ │ │ │ 2.POST /product/add │ │ │ │ │ (name,price, │ │ │ │ │ description, │ │ │ │ │ category,images) │ │ │ │ │─────────────────────> │ │ │ │ │ 3.保存商品 │ │ │ │ │ status=0(待审核)│ │ │ │ │─────────────────>│ │ │ │ │ │ 4.INSERT │ │ │ │ │───────────────>│ │ │ │ │<───────────────│ │ │ │ │ │ │ 5.显示成功消息 │ │ │ │ │ "上传成功，待审核" │ │ │ │ │<─────────────────│ │ │ │

流程说明

  1. 用户填写商品信息（名称、价格、描述、分类、图片）
  2. 后端创建Product对象，status设置为0（待审核）
  3. 保存到数据库
  4. 返回成功消息"上传成功，待审核"

2.2 商品审核流程

商品审核流程允许管理员查看待审核商品并进行审核操作。

序列图

┌──────────┐ ┌─────────────┐ ┌──────────────┐ ┌────────────┐ ┌──────────┐ │ 管理员 │ │ 浏览器 │ │AdminController│ │ProductRepository││ 数据库 │ └────┬─────┘ └──────┬──────┘ └──────┬───────┘ └─────┬──────┘ └────┬─────┘ │ │ │ │ │ │ 1.访问审核列表 │ │ │ │ │─────────────────>│ │ │ │ │ │ 2.GET /admin/products│ │ │ │ │ (status=0) │ │ │ │ │───────────────────>│ │ │ │ │ │ 3.查询待审核商品 │ │ │ │ │─────────────────>│ │ │ │ │ │ 4.SELECT │ │ │ │ │───────────────>│ │ │ │ │<───────────────│ │ │ │ │ │ │ │ 5.返回审核列表页面 │ │ │ │ 6.查看待审核商品 │ │ │ │ │<─────────────────│ │ │ │ │ │ │ │ │ │ 7.点击"通过"按钮 │ │ │ │ │─────────────────>│ │ │ │ │ │ 8.GET /admin/product/{id}/approve│ │ │ │ │───────────────────>│ │ │ │ │ │ 9.更新status=1 │ │ │ │ │ (审核通过) │ │ │ │ │─────────────────>│ │ │ │ │ │ 10.UPDATE │ │ │ │ │───────────────>│ │ │ │ │<───────────────│ │ │ │ │ │ │ 11.重定向到审核列表│ │ │ │ │ 显示成功消息 │ │ │ │ │<─────────────────│ │ │ │

流程说明

  1. 管理员访问商品审核页面 GET /admin/products?status=0
  2. 查询所有待审核商品（status=0）
  3. 返回审核列表页面
  4. 管理员查看商品详情或直接操作
  5. 点击"通过"按钮，status更新为1（已通过）
  6. 重定向回审核列表，显示成功消息
